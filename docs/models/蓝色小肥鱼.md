## 3. 人形骨架（53 根）

标准 VRM 1.0 人形集合，含十指：`hips, spine, chest, neck, head, leftEye, rightEye, shoulder/upper_arm/lower_arm/hand(.L/.R)`，四指三段 + 拇指三段。

拇指的映射是 Blender 导出后的 VRM 1.0 命名：`leftThumbMetacarpal = thumb_proximal`、`leftThumbProximal = thumb_intermediate`、`leftThumbDistal = thumb_distal`（右手同理）。写代码时按 VRM 的 bone 名索引，不要按节点名。

**视线声明为骨骼驱动**：`lookAt.type = "bone"`，`offsetFromHeadBone = [0.03, 0.0354, 0]`，无 rangeMap。也就是说模型作者期望用 **头/眼骨骼** 来跟随视线——插件现在的做法（`gazeFromAim` 驱动 head/eye 骨骼）与声明一致，不需要改成表情驱动。

## 9. 插件现在能用到什么

已经有的（`lib/scene.js`）：

- 模型挂载时会取出 three-vrm 的 **expressionManager** 并挂在 `scene.avatar.expressions` 上（`installAvatar`）；
- 每帧在 `advancePlayback()` 里调用 `vrm.expressionManager.update()`，所以只要把权重写进 expressionManager，画面立刻会动；
- **表情权重有 API**：`scene.setExpression(name, weight)`（`null` ＝交还给自动行为）、`scene.expressionNames()`、`scene.expressionValue(name)`；设置侧读写的是 `preferences.expressions.weights` 这份"钉住"表（`core.setExpressionWeight` / `core.expressionWeightFor`）。
- **动作里的 morph 轨道**：`.vrma` 的 weight 轨道通过 mixer 驱动 expressionManager。**VMD 从 2026-10-12 起不再播放**——`lib/scene.js` 仍认得它的 banner，然后按名字拒绝（VRMA only），所以任何"用 VMD 驱动表情"的写法只属于历史版本。

这个模型的 19 个表情可以这样用（其中前两条插件已经内置）：

- 眨眼：随机间隔触发 `blink`（或左右眼分开做俏皮眨眼 `blinkLeft`/`blinkRight`），间隔在模型参数页的 表情 里配；
- 情绪：被点击 / 拖动释放 / 空闲时切换 `happy` / `sad` / `angry` / `relaxed`，同样是 表情 里的开关；
- 口型：`aa/ih/ou/ee/oh` 可以做成"说话"效果（需要音频或打字驱动）；
- `TiePen`：单一 morph，可做"戴上领带/拿笔"的开关；
- 视线：**不建议**改成 `lookUp/Down/Left/Right` 表情，因为文件声明 `lookAt.type = "bone"`，骨骼驱动才是作者预期的行为；这四个表情可以作为"眼珠额外偏移"的补充。

注意设置界面的现状：**逐个表情的权重滑块表在 2026-10-09 就被删掉了**（`lib/config-page.js` 里留着原因：那张表把面板变成了口型编辑器，而"用哪个表情"现在由 状态与动作 的每状态/每片段 表情·口型 下拉框、以及 部位 的情绪行来决定，选项就是模型自己的表情名）。要手动钉一个权重，用 `scene.setExpression`，或者在 `preferences.expressions.weights` 里留一条。

一个坑：这三个网格的 morph target 没有名字，所以插件里不能靠 `morphTargetDictionary['blink']` 找索引——要么用 VRM expressionManager 的预设名（它内部按 VRM 表建了字典），要么按上面第 4 节的反查表按索引驱动。
