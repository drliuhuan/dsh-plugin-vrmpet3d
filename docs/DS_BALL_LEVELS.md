# DS-BALL 关卡文件

GitHub `ds-ball` 分支的 `assets/game/levels.json` 是关卡发布源，也是插件内置的两关离线副本。插件每次启动后台读取该地址，最长等待 8 秒；网络、HTTP、超时、格式或资源校验失败均不弹窗、不写错误日志，继续使用内置两关。启动与游戏页面不等待下载。

下载完成后，新打开的游戏使用整套新数据。已经打开的游戏保留自己的关卡快照，避免游戏过程中更换布局。更新文件后需要提交到 GitHub `ds-ball` 分支；用户下次启动插件即可后台更新，无需重新构建插件。

## 文件结构

顶层 `version: 1`，`levels` 按顺序包含关卡，`id` 必须从 1 连续递增。每关包含 `id`、`name`、`resources` 和 `bricks`。支持 1–100 关，每关最多 1000 个对象，整包最多 10000 个对象与 2 MiB。

每关独立拥有以下资源，不依赖其他关卡、远端图片地址或可执行脚本：

- `resources.bowls`：以样式名为键的碗样式表。每种样式包括 `shape`（`round` 圆底或 `flat` 平底）、`color` 碗体颜色、`rimColor` 碗口、`baseColor` 碗底、`edgeColor` 边线、`crackColor` 裂痕，以及 `image`。
- `image: null`：按照本关的形状与配色绘制碗；如需要图像，则填写完整的 `data:image/png;base64,...`、WebP 或 JPEG 数据。图像也保存在本关数据里，不另行请求。单张编码不超过 128 KiB，实际使用的宽高不超过 2048 像素。图像未就绪或无法解码时使用本关矢量样式。
- `resources.rice`：米饭的 `heapLight`、`heapDark`、`grain`、`grainShade`、`shadow`、`fill`、`highlight`、`shade` 八种颜色。三种散米轮廓由游戏引擎稳定随机选择。

颜色均使用 `#RRGGBB`。现有两关完全使用资源描述绘制，`image` 为 `null`，不需要额外图片文件。

## 对象属性

`bricks` 中每个对象都写明：

| 字段 | 含义 |
|---|---|
| `x`, `y`, `w`, `h` | 1000×750 游戏坐标中的位置和碰撞尺寸；对象底边不超过 600，给发球留空间 |
| `bowl` | 本关 `resources.bowls` 内的样式名；纯散米使用 `null` |
| `hp` | 碗体可承受的碰撞次数，整数 0–10；纯散米为 0 |
| `rice` | 是否装饭或是否为可食用散米，布尔值 |

装饭碗从上方撞击吃饭，碗仍保留；撞碗体或空碗减去一次耐久并显示裂痕，耐久归零触发碎裂，未吃的饭保留为散米。所有饭吃完才通关。上述规则共用引擎，具体样式、位置、初始饭量和耐久均来自关卡。

每关必须至少有一份饭。第一关为 79 只一击碎白碗；第二关为 104 堆散米与 134 只一击碎深蓝/白碗，完整属性均已写入 JSON。

## 存档兼容

关卡数量由数据决定，新增第三关后无需修改选关、末关判断或通关奖励代码。正式模式只能选择已解锁的关卡，每次通关解锁下一关；解锁进度随存档保存，重新开始或机会耗尽后仍保留。只有 debug 模式可跳到未解锁的关卡，其存档与正式模式分离。相同布局继续精确恢复进度；布局或资源变更时，从该关起点暂停恢复，保留已经获得的机会。旧存档与原两关保持兼容。

后台局部验证：`node scripts/verify-mini-game-levels.mjs`。
